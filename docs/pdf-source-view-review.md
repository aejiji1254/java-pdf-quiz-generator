# 검토 화면 원문 보기·선택 작성 검증

검토 화면에 `문항 상세` / `원문 보기` 탭을 추가했다. 생성 직후 Preview와 저장 세트 수정 화면이 같은 탭을 사용한다. 파일 읽기는 SwingWorker에서 수행하고, 성공적으로 작성·검증한 문항만 기존 목록 반영 경로에 전달한다.

후속 선택 PDF 연결 보완의 검증 기록은 `pdf-chosen-binding-review.md`를 참조한다. 아래 실행 결과는 원문 보기 최초 구현 시점의 기록이다.

## 사용과 연결 범위

- 문항을 선택하면 해당 페이지의 PDFBox 텍스트와 빈 줄을 포함한 줄 번호를 표시한다. 저장된 lineNumber는 별도 하이라이트로 표시하므로, 페이지를 열기만 했을 때 선택 작성 버튼이 활성화되지 않는다.
- 파일명과 `PDF 다시 찾기` 버튼은 원문 영역 위에 항상 보인다. 사용자가 연결한 경우 `(사용자가 선택한 PDF)`를 표시한다. 파일 선택 취소는 기존 연결과 표시를 바꾸지 않는다.
- 연결은 `(세트 ID, 원래 sourcePdf 문자열)`별로 세션 메모리에만 둔다. 서로 다른 폴더의 같은 파일명이나 서로 다른 사람이 보낸 동명 파일을 혼동할 수 있어, 다른 세트 사이에서는 자동 공유하지 않는다. 연결은 등록/재등록 순으로 최대 200개다. 명시적으로 선택한 PDF로 GUI 생성이 성공하면 Preview 표시 전에 등록한다. 같은 세션의 실제 수정본 저장 성공 시에는 직전 부모에 명시적 연결이 있고 sourcePdf가 같은 경우에만 새 ID로 이어준다. 불러오기·가져오기의 부모 메타데이터만으로는 이어주지 않는다.
- 페이지 캐시는 `(정규화한 절대 경로, 페이지)`를 키로 하여 최대 20페이지 LRU다. 각 항목은 표시용 20,000 UTF-16 문자 이내이고, 상한에서 서로게이트 쌍을 끊지 않는다. 줄바꿈은 원본 `split("\\R", -1)` 결과를 LF로 연결하여 표시한다. 원문 줄의 순서·빈 줄·내용은 바꾸지 않는다.
- page가 없는 문항은 `원문 정보가 없습니다`를 표시하고 원문 연결·선택 작성을 비활성화한다. 추출 텍스트가 적어도 보기용 읽기는 글자 수/한글 비율 오류를 내지 않는다. 생성용 읽기 검증은 그대로다.

## 자동 경로의 보안 경계

가져온 sourcePdf를 신뢰하지 않는다. Path를 만들기 전에 문자열 검사로 드라이브 절대 경로 형식과 `.pdf` 확장자를 확인한다. UNC, `//서버`, 확장 경로 접두어, URL, 상대/드라이브 상대 경로, `.`/`..` 경로 조각, 제어·서식 문자, Windows 예약 장치명/잘못된 문자 등은 파일시스템 조회 없이 연결되지 않은 상태로 처리한다. 수동 입력 라벨은 Path로 해석하지 않는다.

드라이브 문자도 네트워크 매핑일 수 있으므로 기본 자동 접근은 시스템 드라이브로 보수적으로 제한한다. 다른 로컬 드라이브는 `PDF 다시 찾기`로 명시 선택할 수 있다. 문자열 검사를 통과한 자동 경로도 NOFOLLOW_LINKS 속성 조회로 루트부터 각 구성 요소를 확인하며, 심볼릭 링크/기타 재분석 지점을 경유하면 열지 않는다. 이 조회는 허용된 로컬 경로에만 적용하며, 거부한 UNC 문자열의 존재 확인은 하지 않는다. 마지막 구성 요소가 일반 파일이어야 한다.

사용자가 파일 선택기로 직접 고른 경로는 명시적 연결로 취급한다. 파일 형식·페이지 수·읽기 성공을 확인한 뒤 연결한다. 늦게 도착한 이전 Worker는 작업 번호 검사로 표시와 연결을 갱신하지 못한다. 오류 안내에는 전체 경로나 하위 예외 메시지를 그대로 노출하지 않는다.

## 선택에서 직접 작성까지

선택 시작 UTF-16 오프셋으로 줄 번호를 먼저 계산한다. 500 code point 초과 선택은 자르지 않고 거부한다. 허용한 선택은 공백·줄바꿈만 공백 하나로 정리하여 `원문 N쪽: …` 해설로 준비한다. 대소문자·전각 문자·문장부호는 변경하지 않는다.

기존 유형 선택/작성 폼을 사용하고 질문·객관식 보기와 정답은 비워 둔다. O/X 보기는 기존 모델처럼 O/X 고정이다. 이 새 흐름에서만 정답이 미선택이며, 적용하면 `정답을 선택하세요`로 안내하고 같은 폼의 입력을 유지한다. 기존 일반 직접 작성의 정답 기본 선택은 유지한다. Workflow가 UUID·MANUAL·세트 sourcePdf 상속·연결 ID null·선택 페이지/줄·직접 작성 접두어를 적용한다. UI에서 선택한 파일 경로는 문항 생성 인자로 전달하지 않는다.

## 기존 흐름과 수정본 검증

기존 addQuestion 시그니처는 유지하며 좌표 인자 null인 새 오버로드로 위임한다. 원본 ID의 순서를 그대로 유지하고, 추가 문항은 새 ID·같은 sourcePdf·MANUAL·연결 ID null이어야 한다. lineNumber가 있으면 page가 있어야 하는 조건과 질문·보기·정답·해설 검증은 기존 SavedQuestion 생성자가 담당한다.

원본 ID 문항의 sourcePdf/page/lineNumber/origin/derivedFromQuestionId 변경은 명시적으로 거부한다. 질문·보기·정답·해설 편집은 허용한다. 수정본 저장의 새 UUID와 바로 직전 부모 연결 기록은 기존대로 유지한다. 생성→편집→수정본 저장 및 v2 메타데이터·가져오기/내보내기 기존 테스트 38개가 수정 없이 통과했다. 기존 좌표 있는 새 문항 거부 테스트는 origin=UNKNOWN인 입력이라 새 조건에서도 그대로 거부된다.
