# 선택한 PDF의 생성 직후 연결 보완

## 동작과 신뢰 경계

파일 선택과 페이지 확인이 성공한 경로를 GUI의 명시적 선택 이력으로 보관한다. 생성 시작 시 PDF 경로와 그 선택 이력을 함께 캡처한다. 생성이 성공하고 해당 작업이 여전히 현재 작업일 때만 반환된 세트 ID/sourcePdf에 기존 PdfPageService.remember()로 연결을 등록한 뒤 Preview를 표시한다. 반환된 sourcePdf가 실제 생성 경로의 절대 정규화 문자열과 같은지도 확인한다.

등록은 PDF 생성 성공 경로에만 있다. 공통 showPreview(), 저장 세트 불러오기, 가져오기, 수동 생성에는 등록 코드를 넣지 않았다. selectedPdf나 불러온 sourcePdf의 문자열만으로 명시적 선택 이력을 만들지 않는다. 같은 ID의 세트를 저장·다시 불러오면 같은 세션의 기존 연결을 재사용하지만 다른 ID에는 적용되지 않는다. 기존 자동 열기 정책 자체는 그대로이므로, 여기서 '미연결'은 명시적 연결이 없다는 뜻이다. 기존 보안 정책에서 허용하는 로컬 파일의 자동 보기까지 금지하는 변경은 아니다.

명시적으로 선택한 UNC도 등록할 수 있다. 이 경우 일반 sourcePdf 문자열을 자동 조회하지 않고, 사용자의 파일 선택에 따른 검증·생성·읽기만 수행한다. 원문 헤더와 PDF 선택 완료 안내에는 파일명만 표시한다.

## 늦은 작업 처리

새 PDF 선택이 수락되거나 유효한 새 생성 요청을 시작하면 작업 번호를 증가시키고 이전 생성을 취소한다. 생성 중에는 PDF 재선택/재생성 버튼을 사용할 수 있고, 페이지 확인 등 다른 작업 중에는 기존처럼 비활성화한다. PDF 선택 취소는 진행 중인 생성을 밀어내지 않는다.

생성 완료 콜백은 작업 번호와 현재 Worker 객체가 모두 일치해야만 결과 표시·연결 등록·busy 상태 해제를 수행한다. 이전 작업이 인터럽트를 무시하고 뒤늦게 반환해도 새 작업 상태를 지우지 않는다. 페이지 수 확인에도 선택 작업 번호와 Worker 객체 검사를 적용했다. 경로 등록에는 완료 시점의 selectedPdf가 아닌 시작 시점의 캡처 값을 쓴다.

파일 선택 대화상자가 열려 있는 동안 이전 생성이 끝날 수 있으므로, 새 파일의 페이지 확인이 성공하면 메인 화면으로 돌아와 그 파일의 생성 범위를 선택하게 한다.

## 연결 크기와 수정본 상속

연결 사전은 최대 200개이며 등록/재등록 순으로 오래된 항목을 제거한다. 조회만으로 순서가 갱신되지는 않는다. 표시 페이지의 기존 20페이지 LRU와는 별개다. 사전과 페이지 캐시는 모두 서비스 인스턴스 메모리에만 존재한다.

GUI에서 수정본 저장이 실제 성공한 직후에만 다음 조건으로 연결을 이어준다.

1. 원본과 수정본의 ID가 다르다.
2. sourcePdf 문자열이 정확히 같다.
3. 수정본의 derivedFromSetId가 바로 그 원본 ID다.
4. 직전 부모에 이미 명시적 연결이 있다. 기존 자동 경로 허용 결과는 승격하지 않는다.
5. 대상에 이미 별도의 명시적 연결이 있으면 덮어쓰지 않는다.

재수정도 직전 부모에 연결이 있어야 한다. 조상 연결을 탐색하지 않는다. 불러온 JSON의 부모 ID·문항 연결·같은 파일명만으로 신뢰를 상속하지 않는다. 가져온 복사본이 로컬 세트를 부모로 가리켜도 불러오기 경로에서는 이 메서드를 호출하지 않는다.

## 정책 주입의 범위

새 GUI 입력/생성 대역과 페이지 서비스의 주입 생성자는 패키지 전용이다. 공개 QuizMakerFrame 생성자는 기존 LocalAccess 보안 정책과 실제 파일 선택/Workflow 입력을 사용한다. 시스템 프로퍼티·환경 변수·설정 파일을 새 정책 전환 수단으로 추가하지 않았다. 기존 SystemDrive 조회는 OS의 시스템 볼륨을 식별하던 기존 동작 그대로다.

이전 테스트들이 사용하는 기존 공개 PdfPageService(Access) I/O 대역 생성자는 하위 호환을 위해 유지했다. 그 API의 가시성을 바꾸거나 기존 테스트를 수정하지 않았다. 이번 GUI 주입 경로가 패키지 전용인지, 공개 GUI 생성자에 이 주입 인자가 없는지, 기본 GUI의 서비스가 LocalAccess인지 새 테스트로 확인했다.

## 요구사항별 검증

| 요구사항 | 검증 |
| --- | --- |
| 기본 1. 선택→생성→즉시 보기 | 자동 열기를 거부하는 정책과 D: 경로 대역을 생성자로 주입해 버튼 선택→페이지 확인→생성→원문 표시를 EDT에서 실행. 실제 sample.pdf 복사본을 기존 Workflow로 생성하는 별도 사례도 거부 정책 하에서 즉시 연결됨을 확인. |
| 기본 1. 불러온 출처는 승격 안 함 | 같은 sourcePdf의 다른 세트와 실제 가져온 복사본을 목록 불러오기 경로로 열어 명시적 연결이 생기지 않음을 확인. |
| 기본 2. 수정본 | 실제 GUI persistReviewed 저장 경로에서 수정본과 재수정본의 연결 유지 확인. 새 서비스에서 부모 연결 없이 다시 수정하면 연결되지 않음. source 불일치·잘못된 부모·동일 ID·기존 대상 연결도 서비스 단위로 거부 확인. |
| 기본 3. 재시작/쓰기 없음 | 새 서비스/새 GUI에서 저장된 같은 세트를 열어 연결이 사라지는지 확인. 생성·등록 전후 임시 폴더 파일 목록/바이트/mtime 동일. 동일 모델을 등록 전과 등록 후에 각각 저장한 JSON 바이트도 동일. |
| 보완 1. 작업 경쟁 | 느린 첫 생성을 주입하고 다른 PDF를 선택하여 생성한 뒤 첫 작업 반환: 이전 Preview/연결이 반영되지 않음. 같은 PDF 재생성 중 새 작업도 대기시킨 상태에서 이전 작업을 반환시켜 Worker/busy 상태가 보존됨을 확인. |
| 보완 1. 경로 캡처 | 생성 도중 selectedPdf만 다른 값으로 바꿔도 처음 경로로만 등록됨. 이어서 선택 이력 없이 바뀐 selectedPdf로 생성하면 등록되지 않음. 파일 선택 취소는 작업 번호·진행 작업·이력을 바꾸지 않음. |
| 보완 2. 주입 범위 | 새 GUI 주입 생성자가 package-private, 공개 생성자에는 서비스 인자 없음, 기본 서비스가 LocalAccess임을 확인. 기존 UNC 자동 접근 거부 테스트도 유지. |
| 보완 3(a). 같은 ID | saveReviewed 후 세트 ID가 유지되고 목록에서 재로드한 원문에 사용자 선택 표시가 남음. |
| 보완 3(b). 다른 ID | 같은 sourcePdf의 새 ID를 저장·불러와도 연결 안 됨. |
| 보완 3(c). 가져온 복사본 | 실제 inspect/commit(asCopy=true)로 새 ID를 만든 뒤 불러와도 연결 안 됨. 원본 JSON 바이트도 동일. |
| 보완 3(d). 수동 입력 | PDF 선택 이력이 있는 GUI에서 수동 생성하더라도 해당 수동 세트에 연결이 등록되지 않음. |
| 보완 3(e). 재수정 | 직전 부모의 명시적 연결이 있을 때만 이어짐. 조상만 연결되어 있고 직전 부모는 미연결이면 거부. |
| 보완 4. UNC | UNC 선택·검증·생성·읽기 대역으로 연결을 확인하고, 자동 경로 검사 호출 없이 파일명만 표시됨을 확인. 실제 네트워크에는 접속하지 않음. |
| 보완 4. 200개 제한 | 200개 등록 뒤 조회만 한 가장 오래된 항목이 201번째 삽입에서 제거됨. 재등록은 새 등록 순서가 되고 새 서비스는 사전이 비어 있음. |

등록은 기존 모델의 sourcePdf 값을 바꾸지 않는다. PDF 생성 세트가 원래 갖는 sourcePdf 경로는 기존 JSON 필드에 그대로 저장될 수 있지만, '사용자가 선택함' 신뢰 상태나 연결 사전·작업 번호는 JSON/설정에 저장하지 않는다. 등록이 추가 JSON 필드나 파일을 만들지 않음을 임시 폴더 스냅샷과 JSON 바이트 비교로 확인했다.

- 기존 GUI·수정본·McBaseline 관련 테스트 23개를 먼저 실행하여 수정 없이 통과했다.
- 신규 JUnit 4 테스트는 ChosenPdfGenerationTest 11개, PdfChosenBindingTest 4개다.
- 최종 `mvn clean test`: **258개, 실패 0·오류 0·건너뜀 0**, BUILD SUCCESS, 2026-11-23 00:57:46 KST.
- 기존 243개 테스트와 McBaseline* PDF/수동/콘솔, 기존 STRUCTURED/추출 캡처 모두 통과했다. **기준 대비 불일치 0건**이다.
- 작업 전 기존 115개 파일의 SHA-256과 비교하여 승인한 제품 3개·기존 문서 1개만 변경되고 111개가 동일함을 확인했다. 기존 테스트·기준 캡처·McBaseline* 도구·pom.xml·Agents.md는 바이트 단위로 동일하다. 새 파일은 테스트 2개와 이 보고서뿐이다.
